# AGENTS.md

OpenTTY: a J2ME MIDlet (CLDC-1.0/MIDP-2.0) that is a Lua-scripted shell + RISC-V ELF emulator. It also contains a Docker/Coolify deployment of the web services (PHP + Python proxies).

## Language

All code, comments, commit messages, docs, and on-device user-facing strings in
this repository must be written in **English** (US), so the project stays
accessible to everyone. Do not introduce Portuguese (or any other language)
text; translate existing non-English content when you touch it.

## Source layout — what edits go where

- `src/` — canonical MIDlet source: `OpenTTY.java`, `Lua.java`, `ELF.java`, `LuaCanvas.java`, plus `src/bin` (built-in `/bin` commands, Lua scripts with `#!/bin/lua` shebang), `src/etc`, `src/boot` (kernel/ramdisk seed files), `src/lib/libcore.so` (a Lua module despite the `.so` name).
- `src/LuaCanvas.java` — the `Canvas` behind `graphics.canvas` (see `docs/LUACANVAS.md`): persistent off-screen buffer, colors, font specs, shapes, cursor/print, clip/translate/save-restore, held keys, pointer, LCDUI commands, and the frame loop (`runLoop`/`animate`). Handles are plain tables whose metatable holds `__canvas` and uses the `graphics.canvas` module as `__index`; callbacks are stored in `LuaCanvas.callbacks` (never in the handle) so they cannot shadow methods, and `__newindex` (`CANVAS_ASSIGN`) routes function values to callbacks and property values to `title`/`font`/`background`/`foreground`/`color`. In loop mode events are queued and pumped by the loop thread (`paint` is suppressed there — the LCDUI thread only blits the buffer). `flush()`/`requestRepaint()` only call `serviceRepaints()` on the LCDUI thread outside `paint` (an `inPaint` flag guards it); a background flush posts one coalesced repaint through `Display.callSerially`, because calling `serviceRepaints()` off the event thread freezes the canvas on real phones. `c:saveImage(path)` is a `-1` stub in `src/` (MIDP cannot read `Image` pixels) and `pc/patch_src.py` swaps in the `java.awt` PNG export for the desktop shim.
- Boot: `src/OpenTTY.java` reads `/boot/grub.cfg` (seeded at `src/boot/grub.cfg`, read via `read()` so an RMS/VFS copy in `/boot/grub.cfg` overrides the seed). Any config with at least one `menuentry` shows a `List` boot menu that waits for the user to pick an entry and press **Boot** (or `List.SELECT_COMMAND`); an empty/missing config boots straight. `set default=N` and `set timeout=N` are accepted but ignored (no preselect, no countdown/auto-boot). `bootSelect` runs synchronously on the calling (UI event) thread — no extra Thread/Runnable. Entries are plain `Hashtable`s with `title`/`root`/`init` keys (no `BootEntry` class). A standard entry (`root=/` + `init=/bin/init`) → `defaultBoot()` login gate; anything else → `bootKernel(root, init)` direct. Entry body: `root=<path>` (`/` = normal OpenTTY, else a FileConnection folder used as chroot) and `init=<path>` (default `/bin/init`). The chosen `root` is stored in `globals["ROOT"]` and `init` is passed as an argument (no global `bootInit`). `chroot` redirects all paths except the global mounts `/boot` `/proc` `/tmp` `/mnt` `/dev` via `OpenTTY.redirect(String)` — applied in `getInputStream`/`write`/`deleteFile` and Lua `dirs`/`chdir`/`MKDIR`. Boot logic lives in `loadBootMenu`/`countBootEntries`/`parseBootEntry`/`parseBootMenu`/`showBootMenu`/`bootSelect`/`bootEntry`/`defaultBoot`/`bootKernel`.
- `apps/1.19/sys/cterm` — the Canvas terminal (`graphics.canvas`): ANSI SGR parser, cell grid, scrollback and an in-canvas line editor (see `docs/CTERM.md`). It is a single self-contained app; loading it with `CTERM_AS_MODULE` set returns the engine table without starting the UI.
- `apps/<major>/` — the on-device app-store catalog, versioned by major release. `apps/1.18/` holds the `file/ net/ sys/ games/ dev/` dirs currently shipping with 1.18.x. Apps are registered in the mirror table in `apps/<major>/sources.lua` (e.g. `["docker"] = { remote = "sys/docker/main.lua", here = "/bin/docker", ... }`), which doubles as the `/etc/sources` file on-device (seeded from `src/etc/sources`). Adding an app means updating the app files **and** the sources mirror. New majors: copy the previous `apps/<major>/` dir; the `remote` paths stay relative to the major dir and `version = "<major>"` inside `sources.lua`. `apps/<major>/lua/` holds the canonical **rock payloads** (`math.lua`, `string.lua`, `graphics.lua`, `kernel.lua`, `httpd.lua`) and `apps/<major>/rocks.lua` is their generated catalog (see `docs/LUAROCKS.md`).
- `luarocks` (`apps/1.19/sys/luarocks` → `/bin/luarocks`) — the Lua rock package manager: payloads declare `-- rock: key=value` headers (`name`, `version`, `description`, optional `here`, repeatable/comma-separated `depends`) and install to `/lib/<name>.lua`; `luarocks index <dir> [out] [prefix]` regenerates `apps/<major>/rocks.lua`, `update`/`switch <version>` refresh `/etc/rocks` from `server/apps/<version>/rocks.lua` (seeded from `src/etc/rocks`), and installed state is `/etc/rocks.installed`. `install`/`remove`/`update`/`switch` require uid 0. `require` loads `/lib/<name>.lua`; `src/lib/math.lua` is the shipped seed copy of the math rock and `tests/check_sources.py` keeps it byte-identical. Rocks extend the existing globals (`local M = math or {}`) and return the table, because `require` caches the result. Publishing: add `apps/<major>/lua/<name>.lua`, stage the payloads under `/mnt/opentty/rocks/` (io.dirs cannot list `apps/`), run `luarocks index`, copy the output to `apps/<major>/rocks.lua` **and** `src/etc/rocks`, then `python3 tests/check_sources.py`.
- `res/` — embedded resources (bundled apps, pages). `res/lib/` holds the guest C runtime for the emulator, **ported to RISC-V RV32I**: `lib32.s` (full asm stdlib, `-lib`) and `libc.s` (thin `li a7,#LIB_*; ecall; ret` wrappers, `-stdlib`). `lib32.s`'s `print_decimal`/`udiv10` are software (no M-ext needed); its `sbrk` tolerates the emulator rounding `brk` up to 4K. `libc.s` also implements `qsort`/`bsearch` in guest assembly (insertion sort / binary search) because their comparators are guest function pointers.
- `res/archive/elf/` — emulator archives for `res/swap_lite.sh`: `Full.java` (full RV32IM emulator, backed up here) and `Lite.java` (lite stub, marker `// ELF Lite`). `swap_lite.sh` swaps `src/ELF.java` between them; the legacy `res/archive/ELF.java`/`ELF.full.java` are stale pre-RISC-V files.
- `build-elf.sh` — builds RISC-V RV32IM ELFs for the emulator (`ET_EXEC`, ELF32 LE, `EM_RISCV`=243, entry ≤ 1 MB). Flags: `-T <addr>`, `-entry <sym>`, `-shared`, `-lib` (links `res/lib/lib32.s`, drop-demo-`main` via awk), `-stdlib` (links `res/lib/libc.s`), `-keep`; `CROSS=` overrides the toolchain search (`riscv64-unknown-elf-`, `riscv64-linux-gnu-`, …). `.c` files compile with `-march=rv32im -mabi=ilp32 -fno-builtin`; `as` runs with `-march=rv32im -mabi=ilp32` (`ASFLAGS` array) and `ld` with `-m elf32lriscv` (`LDFLAGS`) — keep those arrays, not embedded flag strings, so quoted `"$AS"`/`"$LD"` calls work.
- `lua/` — removed: the host-side Python port of the J2ME runtime (formerly `lua/runtime.py`, `lua/run.py`, `lua/sys/`) was deleted in 1.18.2.
- `pc/` — **desktop development shim**: runs the unmodified `src/` on desktop Java (JDK 17+) via J2ME stubs (`pc/j2me/`) and `pc/run.sh`. `run.sh` copies `src/` to `pc/work/`, runs `pc/patch_src.py` (a mechanical, behavior-preserving patcher: adds the single-type `List` import, wraps every `switch` `case`/`default` label in braces, renames the Lua.java shadowed locals `arg`→`arg0`/`argv`/`kpid`/`inOut`/`dargs` over text-anchored spans (`ARG_ANCHORS` plus the `exec()` decl→`splitAmpersands` span, so edits elsewhere in Lua.java never shift them), neutralizes the `write` finally-close, and patches `Lua.run()` to reset `tokenIndex` / guards exec's `.` branch), then compiles `src` + `pc/j2me` + `pc/app` in one `javac` run and `exec`s `java -cp "$BUILD:$ROOT/src"` (repo root on the classpath so `/etc`, `/bin`, `/boot`, `/lib` resources resolve). `pc/build-jar.sh` packs the same build (classes + guest resources at jar root) into `dist/OpenTTY-desktop-1.19.jar`. `OpenTTYMain.main` parses the same CLI as `run.sh` (`root=`/`init=`/`--user`/`--smoke`/`--watchdog`/`--cmd`/`--` + host-file staging into `data/mnt/opentty/`), but only when `opentty.cmd` is not already set. Non-reparenting WMs (bspwm/i3/dwm...) leave AWT windows blank grey until ReparentNotify — `run.sh` sets `_JAVA_AWT_WM_NONREPARENTING=1`; `java -jar` users must set it too. `Display.rebuild()` coalesces repaint requests on the EDT (a request during a rebuild must still be followed by another pass, or console output may never repaint). Custom app behavior via JVM props: `OPENTTY_USER`, `OPENTTY_JVM_OPTS` (plus `opentty.cmd`, `opentty.bootRoot`, `opentty.bootInit`, `opentty.hostname`, `opentty.execdbg`, `opentty.repro`, `opentty.watchdog`, and the gated UI diagnostics `opentty.probe` / `opentty.dumpui`, the latter with `opentty.enterTest=1` to automate an Enter keystroke against the xterm input row). Desktop UI conventions: Form rows render into the shared `Display.body` via `GridBagLayout` rows that fill the full column width (`resetBody`/`addBodyRow`, `pinGridTop` holds rows at the top; the console `JTextArea` is wrapped in a full-width `BorderLayout` panel so output text stays flush against the left edge — BoxLayout Y_AXIS left a big empty margin); Enter in the xterm input row and a focused command button both fire the Form's `Run` command (`fireRunCommand`, button `ENTER` key binding); `MIDlet.notifyDestroyed()` disposes the window via `Display.notifyDestroyed()` and `System.exit(0)`, so `destroyApp` (Exit command, `exit`, emulator end) closes the desktop window instead of leaving a zombie JVM. Device behavior: a first run with an empty `data/rms` shows the `OpenTTY - Login` form to create user + password (exactly like the J2ME MIDlet — creds are written to `OpenRMS` records 1/2 and the "Reopen MIDlet" alert then `Exit` closes the window); the runner only pre-seeds credentials when `--user`/`--pass` are given (`-Dopentty.user`/`-Dopentty.pass`), so headless/scripted runs and `--smoke` must pass them to reach the console; the boot menu (List `OpenTTY - Boot`) appears whenever `/boot/grub.cfg` has more than one `menuentry`, and everything — credentials, record stores and the VFS index (record 3) — persists across runs under `data/rms` (a root `init=` script can write `/boot/grub.cfg` via `io.write` to install boot entries). `pc/app/OpenTTYMain.java` has `opentty.smoke` mode (boot the MIDlet headless, dump `Display.staticCurrent()` + OpenRMS records, fire the xterm Run handler with a command, `System.exit(0)`). The interactive path mirrors the MIDP model: MIDlet runs on its own worker thread while `Display` marshals all UI onto the Swing EDT. Latest verified: boots to `/bin/xterm` Form and executes shell commands through the Run handler; `-- /path/app.lua` (staged, `.`-sourced Lua), `-- /path/count.elf` (staged ELF), `init=<file>` and `root=<dir>` all run end-to-end in the JAR.
- `kernel/` — legacy ARM32 assembly kernel (`vmlinuz.s`) built into an `ET_EXEC`/`EM_ARM` ELF (`kernel/vmlinuz`). It is not loadable by the current RISC-V-only `src/ELF.java`; `src/boot/vmlinuz` is its seed placeholder on the RAM disk.
- `dist/archive/<ver>` — per-version filesystem snapshots of the app store, plus the release jar (`OpenTTY-<ver>.jar`).
- `nbproject/project.properties` — NetBeans J2ME project config (MIDlet-Version 1.19, jar/jad names).

## Build

- The real build happens **on-device** with the J2ME SDK (see `docs/BUILD.md`), producing `dist/OpenTTY.jar` + `dist/OpenTTY.jad`. For quick host-side iteration use the `pc/` desktop shim (see above); `src/` itself needs a J2ME toolchain.
- **Build versioning** (`src/OpenTTY.java` `build` string + a new line in `res/build.txt`): format `YEAR-major.version-NNxMM` (e.g. `2026-1.18.2-04x41`). The `MM` counter increments by one per build and only ever goes to `99`; when `MM` reaches `99`, the `NN` prefix increments and `MM` resets to `1` (`04x99` → `05x01`). Never skip ahead: after `04x40` the next build is `04x41`, **not** `05x41`. Keep the orphan `x1`-style wraparound in mind (there is no `x00`/`x100`).
- Sanity-check every Lua script you touch with: `lua -e "assert(loadfile('<file>'))"`.
- Host-side runtime checks: run the desktop shim **headless** so no window pops up on the user's desktop, and batch every check into one script/run (repeated windowed launches are unwelcome): `OPENTTY_JVM_OPTS="-Dopentty.headless=1" bash pc/run.sh --user opentty --pass opentty --smoke -- /tmp/opencode/all-test.lua`. Headless (`-Dopentty.headless=1`, also honored via `java.awt.headless=true`) keeps screens/canvases fully functional — sizes, drawing, keys, loops — it only skips painting. Scripts write results to `/mnt/opentty/<file>` (host `data/mnt/opentty/<file>`).

## Lua runtime gotchas (verified in `src/Lua.java`)

- Metatables: `setmetatable`/`getmetatable`/`rawget`/`rawset`/`rawequal`/`rawlen` are native; `__index` (table chain or function), `__newindex`, `__call`, `__tostring`, `__len`, `__eq`/`__lt`/`__le` and `__add`/`__sub`/`__mul`/`__div`/`__mod`/`__pow`/`__unm`/`__concat` dispatch through `getMetatable`/`metaField`/`indexValue`/`indexSet`/`callMeta`. The metatable is stored **inside the table** under the `__metatable` key (no registry, so no per-table leak); `luaLength()` (size minus that slot) backs `#`, `rawlen`, `select("#")` and the `table` library, and the generic `for` loop skips the key. Keep any new size/iteration path metatable-aware. `function t:m()` is still a parse error — use `t.m = function(self) ... end`.
- `debug.traceback` / `debug.getinfo` / `debug.getregistry` live in the `debug` table (constants `DEBUG_*`); frames carry `name/source/line`, and `call()` refreshes the parent frame line at each call site (plus the throwing frame in its `catch`) so tracebacks show call sites. `debug.getlocal`/`setlocal`/`sethook` are not implemented.
- `return f()` forwards every result of the call (the `RETURN` statement evaluates its expressions **before** setting `doreturn`, otherwise the callee's body aborts after its first statement — that flag also double-wrapped results).
- Function bodies are collected by copying tokens until the matching `end`: `factor()` for anonymous functions (table-constructor handlers such as `graphics.handler(t, { [cmd] = function(...) ... end })`), the `local function`/`function` statements for named ones, and the loop/`do` statements for their blocks. Every collector must copy each token **once**: the anonymous-function path used to add a nested `end` twice, so the first nested `local function` inside such a handler ended at its first one-line `if ... end` and the rest of its body ran in the handler frame (nil locals, `ArithmeticException`, bogus line numbers). `tests/lua/check_runtime.lua` guards this shape.

- `string.format`, `string.rep`, `string.gsub`, `string.gmatch` do **not** exist natively. Available string funcs are only: `upper lower len find match reverse sub hash byte char trim uuid split getCommand getArgument env getpattern startswith endswith`. The `docker` app crashed with "Attempt to call a non-function value" because it used `string.format`/`string.rep` — do not reintroduce them into scripts that do not `require("string")` (the `string` rock adds `format/rep/gsub/gmatch/lpad/rpad/join/lines/replace/text2note` plus a pattern engine).
- Generic `for` supports table/`pairs`/`ipairs` sources **and function iterators** (`for w in gmatch(s, p) do`, `for v in counter(n) do`, `for v in f, state, control do`); a call used as the iterator is unwrapped to its first result. `break` inside a numeric `for`/`repeat` body no longer leaks into the enclosing loop (the flag used to stay set when the broken iteration was the last one, which silently truncated the `string` rock's pattern engine after the first capture group).
- `load(code)` compiles **and runs** the chunk, returning its results (it is `exec`, not stock Lua's chunk loader); `pcall(load, code)` is the safe way to load a module file by hand.
- Division by zero throws (`n / 0`, `x % 0`): there are no `inf`/`nan` literals, so libraries build them arithmetically (double a number until it stops changing for infinity, `math.huge - math.huge` for NaN). Exponent literals (`1e10`) are also unsupported.
- `table.remove` captures the length before shifting: `table.remove(t, 1)` returns the old head and moves every element; `tests/lua/check_runtime.lua` guards it.
- `#f()` on a call result is unreliable (it can return `1` or throw): assign the result to a local first (`local plain = T.strip(text)` then `return #plain`). `table[field]` inside an `and`/`or` chain can also read nil, so copy the key to a local (`local name = node.name`) before `t[name]`. Both shapes are avoided in the rock payloads.
- File reads return bytes verbatim: `io.read`/`require` use `OpenTTY.envVars`, which only expands `$VAR`, and `Lua.toLuaString` no longer calls `escape()`. `OpenTTY.escape` (decodes `\n`, `\t`, `\\`, `\.`) belongs to command-line expansion only (`midlet.env`); applying it to values corrupted every Lua source that contained `"\\"`.
- `io.dirs(path)` returns entries only for `/tmp/`, `/mnt/<sub>` (real FS), and exactly `/bin/`, `/etc/`, `/lib/`, `/boot/`, `/home/`; any other path yields an empty table.
- `string.startswith`/`endswith` are native — don't shadow them with Lua reimplementations.
- Daemon convention (matches how `os.request(1, "serve", path)` spawns services in `Lua.java`): daemon apps must check `arg[1] == "--deamon"` (**the typo is the convention** — other daemons in `apps/` use it), name themselves with `os.setproc("name", ...)`, and end with a top-level `return function(payload, args, scope, pid, uid) ... end` as the handler.
- `/bin/init` is PID 1 with the kernel handler: `os.request(1, payload, arg)` implements `sendsig`, `serve`, `rms`, `user`/`useradd`/`userdel`, `setsh`, `netsh`, etc.
- Java exceptions (e.g. `java.lang.NullPointerException`) carry no message. The runtime appends a **Lua-side traceback** — `Lua <file>:<line>`, a caret-backed copy of the offending source line (`^---` + `near '<token>'`), and a `stack traceback:` of the Lua function chain — via `Lua.getTraceback(e)`, used in `run()`, `pcall`, `os.request` handler failures, background threads, and UI callbacks. This depends on `Token.offset` (absolute char offset recorded in `tokenize`), `lastCode`, `frameStack`/`thrownFrames`, `thrownTokens`/`thrownTokenIndex` (set by `recordThrow()` in `run()`/`LuaFunction.call()`), `pointerBlock()`, `tokenLexeme()`, and `LuaFunction.name` — keep these in sync in `src/`. Errors contained by `pcall` (and `require`/`load` call sites via `exec`) reset the thrown state so later tracebacks point at the real spot.

## ELF emulator (`src/ELF.java` — RISC-V RV32IM core)

- Machine: `EM_RISCV`=243, 32-bit, 1 MB guest RAM, `registers[32]` (x0 hardwired 0; `REG_SP`=2 x2, `REG_LR`=1 x1/ra, `REG_A0..A3`=x10..13, `REG_A7`=x17/a7). Decoder: RV32I (LUI/AUIPC/JAL/JALR/BL* /LBHWLHU/SB/SH/SW/ALU/SLL*/SR* /FENCE/SYSTEM) + M-ext (MUL/MULH/MULHSU/MULHU/DIV/DIVU/REM/REMU). Syscall via `ecall` → `handleSyscall(registers[REG_A7])`; `ebreak` stops.
- Guest C library via lightweight SYSCALL wrappers (`LIB_BASE=1000`): ids 1000–1063 in `ELF.java` `handleLibraryCall` cover string (`strlen…strdup`, `strstr`, `strrchr`, `strcasecmp`/`strncasecmp`, `strtol`/`strtoul`), `atoi`/`abs`/`toupper`/`tolower`, memory (`memcpy/memmove/memset/memcmp/memchr`), IO (`putchar/puts/printf/sprintf/snprintf`), heap (`malloc/calloc/realloc/free`), `getpid`, RISC-V runtime helpers, LCDUI (`res/lib/lcdui.h`), `graphics_taskmngr`, and `opentty_setproc(key, value)` for ELF process name, registered screen, command and database values; plus `gc()`/`mem_total`/`mem_free`/`mem_used` (host Java heap in KB) and a raw `time` wrapper (SYS_TIME 13) in `res/lib/libc.s`. `exit/_exit/abort` = syscall 1. Raw Linux syscalls use ARM EABI numbers in a7 (`write/read/open/close/brk/…`); the full supported list (1–295) in `docs/ELF/README.md`. Handlers: `handlePipe` (SYS_PIPE 42, in-process FIFO via `PipeBuffer`/`PipeReadEnd`/`PipeWriteEnd` wired into `handleRead`/`handleWrite`/`handleFstat` as `S_IFIFO`, no fork), plus `handleAlarm`/`handleAccess`/`handleSetsid`/`handleGetrusage`/`handleReadlink`/`handleSethostname`/`handleGethostname`; per-process fields `processUmask` (SYS_UMASK 60), `hostName` (resolved by `OpenTTY.hostName(scope)`: a name set in `/etc/hostname` wins, otherwise the real machine name the desktop shim publishes as `opentty.hostname` (`OpenTTYMain` sets it from `$HOSTNAME`/`InetAddress`), otherwise the seed `localhost`; SYS_SETHOSTNAME 170 also persists to `/etc/hostname`, SYS_GETHOSTNAME 172), `alarmLeft` (SYS_ALARM 27), `proc.priority` (SYS_*PRIORITY). Path helpers `readGuestCString`/`guestPathExists` back `access`/`readlink`.
- LCDUI: `ELF` itself implements `CommandListener`, `ItemCommandListener` and `ItemStateListener`; it owns Displayable/Item/Command handles and queues `{type,screen,command,index}` events (`1` screen command, `2` list select, `3` item command with `screen` = item handle, `4` item state with `index` = selected index). `lcdui_wait_event` suspends the guest when empty; the listener callbacks enqueue the event and resume it. On ELF exit/crash, cleanup removes its process and restores another registered process screen, matching Lua. Do not add a listener class for this path.
- LCDUI widget parity with the Lua `graphics` package (`res/lib/lcdui.h`, `LIB_UI_*` ids): `lcdui_alert(title, text, type, timeout)` + `lcdui_show_alert(alert, next)`, `lcdui_set_ticker`, `lcdui_append_gauge`/`set_gauge`/`get_gauge`, `lcdui_append_spacer`, `lcdui_append_image`, `lcdui_append_choice` + `choice_append/selected/set_selected/count`, `lcdui_append_button` + `lcdui_item_command`/`set_default_command`, `lcdui_set_font` (Lua style strings via `uiFont`) / `lcdui_set_layout` (MIDP `LAYOUT_*` bits), `lcdui_get_label`, `lcdui_delete`, `lcdui_insert_text`, `lcdui_size`, `lcdui_list_append_image`, `lcdui_list_selected`, `lcdui_get_current`, `lcdui_vibrate`. Item listeners are installed by `lcdui_display` (Forms get `setItemStateListener`); `lcdui_demo` in `res/apps/src/lcdui-demo.c` is the showcase.
- Guest `_start` CRT reads args from the stack: `[sp]=argc`, `[sp+4]=argv`, envp after the NULL (initial SP 16-byte aligned).
- `printf`/`sprintf` support `%s %c %d %i %u %x %X %o %p %%` with `l`/`h` (32-bit) and `ll` (64-bit); `%f/%e/%g` consume a 64-bit arg and print `0` (no float). Flags/width/precision parsed and ignored.
- Varargs follow the RISC-V convention: 32-bit args arrive in a0–a7 (x10–17) then `[sp]…`; a 64-bit (`long long`) arg must live in an **even** register pair and on the stack is 8-aligned. `ELF.java` walks params via `libcArgReg`/`libcArgSpOff` (`libcNext32`/`libcNext64`) — keep in sync.
- Heap: first-fit with split, header `{size,next}` at payload−8, new regions from `findFreeMemoryRegion` (default 64 KB, rounded up to fit the request, so large single allocations work). The free list is address-ordered, so `libcFree` merges neighbours (`libcFreeInsert`, double frees are ignored), a block ending at the bump pointer is released back to the region (`libcHeapTrim`), and `libcRealloc` shrinks/grows in place when the neighbour allows it before falling back to malloc+copy+free.
- `setjmp`/`longjmp`: jmp_buf saves all 32 registers (x0..x31) + pc at offset 128 (buf ≥ 132 bytes).
- Demo ELF: `/tmp/opencode/mkrv.py` builds a hand-RV32I `rvtest.elf` (write + exit); `TestRV.java` runs it against the stubs. Host-side `javac -d /tmp/jc -cp /tmp/opencode/tty-stubs src/ELF.java /tmp/opencode/tty-stubs/{Lua,OpenTTY,Process}.java` for typechecking. **Dynamic linking (`.so`) works on RISC-V**: `loadSharedObject` reads dynsym/dynstr/relocs from guest `memory` and applies `.rela.dyn`/`.rela.plt` (RELA, 12-byte) with `R_RISCV_32/RELATIVE/COPY/JUMP_SLOT/GLOB_DAT`; the executable side does the same (`processSymbols`/`processRelocations`), with copy relocs (`importdemo`) and eager JUMP_SLOT resolution via `resolveSymbol` (libc stubs under `globalSymbols["libc.so.6"]`, app `.so` under their DT_NEEDED name). `setupPLTGOT` writes only GOT[0]=dynamic — lld's RISC-V `.got.plt` uses GOT[2] as the **first** function slot, do not zero it. All supported PLT relocations resolve eagerly; unresolved symbols retain a zero GOT slot.
- Sample C apps: `res/apps/src/*.c` → `res/apps/dist/<name>`; the ones using `-stdlib` now build against the RISC-V `res/lib` port (LLD/`llvm-mc` can also validate: `llvm-mc -triple=riscv32 res/lib/*.s` and `ld.lld -m elf32lriscv`).

- `Dockerfile`: `php:8.3-fpm-alpine` + nginx + supervisor. Services started by `supervisord`: php-fpm, nginx, `python3 server.py` (TCP `:31522`, the OpenTTY mirror service), and `pproxy/app.py` (TCP `:4096` + Flask web on `:10141`).
